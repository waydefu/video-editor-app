## 已修復、並補測的問題

1. **外專案預覽授權順序**：工作區 `get`／`latest` 先驗證 owner，後授權 `source-media://subtitle` 影片連結；外專案索引誤指時不再把外部影片加入許可清單。新增錯置索引回歸。
2. **切換專案與非同步字幕讀取競態**：字幕工作區讀取、證據影格、預檢及 AI 檢查狀態讀取加入專案操作守衛，切換期間不得返回或操作混合專案結果。
3. **遠端控制啟動失敗**：監聽或 QR 配對初始化失敗後清理 server、監聽、訂閱與 session 狀態，後續可以正常重試；新增故障重試測試。
4. **Windows 另存專案檔案識別**：同一 `.swproj` 路徑只改大小寫不再誤判成 Fork，也不會無故重設 projectId；新增 Windows 路徑測試。
5. **同時開啟／另存**：拒絕在專案切換尚未完成時開始另一個相同作業，防止兩個對話框競相寫入主專案。
6. **YouTube 重試計時器**：正常等待完成即移除 AbortSignal 事件監聽；取消時仍按 AbortError 中止，避免長時間任務累積監聽器。
7. **字幕草稿儲存路徑**：從 JSON 讀取的 `draftPath` 必須符合工作區 ID 及影片檔名所決定的目標路徑；若檔案受竄改則拒絕寫入，已加入外部檔案不覆寫測試。
8. **失敗時的暫存檔**：獨立字幕與逐筆 AI 檢查工作檔寫入失敗時，清除本次建立的 partial 檔，避免殘留不完整工作。
9. **YouTube 最後 308**：若 Range 已確認整個檔案完成，但影片 ID 尚未返回，使用可續傳工作階段狀態查詢，而非立即判定上傳失敗；新增回歸測試。

## 未完成／仍需獨立驗收

- `workspace.json`、草稿 SRT 與最新指標是多檔持久化，沒有跨多檔案、跨斷電的交易式提交；目前屬需後續設計資料一致性復原的風險。這次只處理 partial 檔清理與越界路徑。
- YouTube 真實網路不確定性、OAuth、過期工作階段、長片跨斷線續傳需取得安全的測試頻道與真實回應；目前 CI 為模擬 HTTP 回應驗證。
- 4K 長片多磁碟 TEMP、正在搬移時拔碟、GPU 編碼器、多聲道音訊、手機多網卡 LAN 控制，皆未取得實機驗收證據。
- 帶授權音效的 `package:win`／`smoke:packaged` 仍依賴外部 MP3 檔案與核准 SHA，缺少檔案不可宣稱可攜版完成。
- 實際 Windows 視窗 A→B→A、舊版檔案回復、使用者原始素材 SHA 驗收尚未執行。
